# VLM による失敗の自動診断 (結果と限界)

失敗した rollout 動画を、Colab の GPU 上のオープンな VLM
(Qwen2.5-VL-7B-Instruct) に見せ、失敗の種類を診断させた。
課金・API キーは使っていない。

## 正解ラベル
正解は、人 (AI を含む) が動画の静止画から付けた目視ラベルで、確実ではない。
判別できた 8 本: alphabet soup 4/24/25/26/28 = carry_incomplete (カゴの近くまで
運んで時間切れ)、bbq sauce = wrong_target (別の瓶を倒す)、
cream cheese = touch_no_grasp、ketchup = no_approach。

## 4 通りの方法
| # | 方法 | 種類の一致 (8 本) |
|---|---|---|
| 1 | 自由記述 JSON・8 コマ・384px | 3 / 8 |
| 2 | 定義を具体化・コマ別メモ・10 コマ・448px | 3 / 8 |
| 3 | 作業領域を切り出し、コマごとに はい/いいえ | 全コマ「いいえ」 |
| 4 | 切り出し + 選択肢 A〜E + ルール判定 | 1 / 8 |

「いつも carry_incomplete と答える」だけで 5 / 8 当たるので、どれもそれ以下。

## 方法 4 の、成功・失敗の検出 (シミュレータの成否が正解)
- 成功した動画 11 本: 持ち上げを検出 5 本、カゴまで検出 1 本
- 失敗した動画 10 本: カゴまで誤検出 0 本、持ち上げを検出 1 本
- 答えたときは正しいが、見落としが多い (精度は高く、再現率は低い)

## データ追加の提案
入力に「物体ごとの試行数・失敗数・失敗率」を渡すと、失敗した 6 物体に追加する
提案が出た。選ばれた物体は、人が 3 周目で選んだ 5 種類 (+ alphabet soup) と一致。
ただし決め手は失敗率で、診断の種類ではない。

## 結論
小さなオープン VLM では、小さな動画から失敗の種類を当てるのは難しい。
大きな VLM、手元の切り出し、より多いコマ、API 経由の大きなモデルは今後の課題。
