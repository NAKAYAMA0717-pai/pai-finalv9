# ロボットの失敗を、周ごとに直す
SmolVLA × LIBERO-plus ― Physical AI講座 2026 最終課題

公開されていた学習済み SmolVLA を LoRA で追加学習し、
LIBERO-plus の **Object(10種類の物体をカゴに入れる)** の失敗を、
**1周に変えるものを1つだけ**にして減らしました(3周+ぼやけ対策の4周目)。

| 周 | 変えたもの | Object 10種類の成功数 |
|---|---|---|
| 1周目 | 基準(Spatial だけで学習・既定の設定) | 0 / 10 |
| 2周目 | 推論の `n_action_steps` 50 → 10(再学習なし) | 5 / 10 |
| 3周目 | 失敗した5種類の物体のデモを各20本に増やして再学習(学習率 3e-4) | 6 / 10 |
| 4周目 | 3周目と同じ設定 + 学習画像にぼやけを混ぜて再学習 | 7 / 10 |

- 各物体の最初の環境(背景の模様を変えた条件)を1回ずつ評価(seed 固定)。サンプルは小さい。
  **3つの条件に広げた 30 回では 3周目 13/30、4周目 16/30**(下の「さらに調べたこと」)。
- 物体名:alphabet soup=アルファベットスープ / bbq sauce=バーベキューソース / butter=バター / chocolate pudding=チョコレートプリン / cream cheese=クリームチーズ / ketchup=ケチャップ / milk=牛乳 / orange juice=オレンジジュース / salad dressing=サラダドレッシング / tomato sauce=トマトソース
- 他の作業は 3周目でも悪化なし(配置の課題=Spatial 3/3、目的の課題=Goal 2/3、長い作業=libero_10 3/3)。
  Spatial は物の置き場所が違う作業(1周目で学習に使用)、Goal は同じ場面で目的が違う作業、libero_10 は手順を複数つなげる長い作業。
- 効いたのは推論の設定変更。3周目の学習の効果は +1(ketchup)で小さい。
- 残った失敗: bbq sauce / chocolate pudding / cream cheese / orange juice。

## さらに調べたこと: 見直しの間隔・適応型・条件の違い
2周目で効いた「見直しの間隔」を、10種類の物体 × 3つの条件(背景の模様・ぼやけとカメラの向き・照明)
= **30回**で、3周目のモデルについて 5 つの設定で比べた(seed 固定、Colab L4)。

| 設定 | 成功 | 推論回数/エピソード | 1回の時間 | 使える時間(20Hz想定) | 判定 |
|---|---|---|---|---|---|
| 5動作ごと | 15/30 | 45.5 | 327 ms | 250 ms | 間に合わない |
| **10動作ごと** | **13/30** | 23.3 | 326 ms | 500 ms | 間に合う(実用的) |
| 適応型(10/25) | 11/30 | 18.4 | 330 ms | 500 ms〜 | 間に合う |
| 25動作ごと | 8/30 | 10.7 | 330 ms | 1250 ms | 間に合う |
| 50動作ごと | 3/30 | 5.7 | 334 ms | 2500 ms | 間に合う |

- **見直しが細かいほど成功が増える**(3 → 8 → 13 → 15)。2周目の結果が別の条件でも再現した。
- **実用的なのは10動作ごと。** 推論は設定によらず約 330 ms。制御を 20Hz(1動作 50 ms)と
  仮定すると、5動作ごと(250 ms)は間に合わない。15/30 と 13/30 の差は 30 回では偶然と区別できない
  (13/30 の 95% 信頼区間は約 27〜61%)。20Hz は仮定であり、実機の仕様ではない。
- **適応型(つかんだかで見直しを変える)は、上乗せがなかった。** グリッパーの開きが、
  つかむ前から半分以上かつ 0.3 以上閉じたら「つかんでいる」と判定し、つかむ前は10動作、
  つかんだ後は25動作ごとに見直す。推論回数は 23.3 → 18.4(約2割減)だったが、成功 11/30 は
  固定10と固定25を結んだ線上(同じ回数なら約 11.1)とほぼ同じで、間隔を普通に選ぶのと同じ効果だった。
- **条件で結果が大きく変わる。** LIBERO-plus は、同じ作業に背景・照明・カメラの向き・ぼやけなどの
  変化をつけた別バージョンを用意している。各物体の別バージョンを先頭・中ほど・末尾から選ぶと、
  結果的に次の3群になった(分類はリポジトリの `task_classification.json`)。

| 設定 | A 背景の模様(10) | B ぼやけ8・カメラ2(10) | C 照明(10) |
|---|---|---|---|
| 10動作ごと | 6/10 | **0/10** | 7/10 |
| 5動作ごと | 6/10 | 1/10 | 8/10 |
| 25動作ごと | 1/10 | 1/10 | 6/10 |
| 適応型 | 5/10 | 0/10 | 6/10 |

  A の10動作ごと(6/10)は3周目の評価と一致する。背景や照明が違っても 6〜7/10 だが、
  **ぼやけやカメラの向きが変わると、どの設定でもほぼ 0**。見直しの間隔では直らない種類の失敗。
  B の「ぼやけ」は、メインカメラの映像だけにモーションブラー(6回)かガウスぼかし(2回)がかかったもの。
  **README 冒頭の「0 → 5 → 6」は A(背景の模様)だけの結果。**
- 結果: `results/runs/r3_object/replan_sweep.json`(task_id ごとの成否・推論回数・時間)

## ぼやけへの対策(B を直せるか)
| 方法 | 内容 | ぼやけの8回 | 30回の合計(A/B/C) |
|---|---|---|---|
| (3周目) | 補正なし | 0/8 | 13/30(6/0/7) |
| ① 推論前の補正 | メインカメラ画像にアンシャープマスク(弱 σ1.5・量1.0 / 強 σ3.0・量2.0) | 0/8(弱・強とも) | — |
| ② 学習に混ぜる(4周目) | 3周目と同じ設定で、メインカメラの学習画像に確率0.5でぼやけ(モーションブラー7割・ガウス3割) | 0/8 | **16/30(7/0/9)** |

- **ぼやけには2つの方法とも効かなかった。** カメラの向き(2回)も 0/2 のまま。
- 合計は 13→16(A +1、C +2、成功→失敗なし)だが、30回では誤差の範囲(13/30 は約27〜61%、16/30 は約36〜70%)。
- **検証のミスを直した:** ①の最初の検証は、補正するカメラ名(front)が合わず1回もかかっていなかった。
  かかったカメラ名をファイルに残す確認(`PRE_MARK`)を足してやり直した。②も、学習中にぼやけがかかった枚数を記録し、かからなければ止まる。
- 結果: `results/runs/r4_blur/`(`blur_test2.json`、`all_blur_fix.json`、`r4_all.json`)

## 今後の改善するとしたら
1. ぼやけをもっと強く・種類を増やして混ぜる、学習量を増やす、ビジョンエンコーダも学習する、カメラの向きを変えたデータを足して、B の 0/10 を直せるか確かめる
2. 各条件を 100 回以上にして、誤差つきで比べる(+1 や設定間の差が偶然かを確かめる)
3. 実機に近い条件で、推論の速さと成功を合わせて測る
4. VLM の診断の精度を上げる(大きな VLM、手元の切り出し、コマ数)。当たれば提案どおりにデータを足して確かめる
5. alphabet soup の時間切れと動作の速さ、指示文の言い換えへの強さを調べる

## 失敗の診断を VLM に任せる試み
失敗した動画をオープンな VLM (Qwen2.5-VL-7B, Colab の GPU 上、課金なし) に診断させ、
失敗の種類と、データを足す物体の提案を出させた。
- 失敗の種類の診断は、目視ラベルとの一致が 3/8 〜 1/8 で、当てにならなかった。
- 成功した動画 11 本のうち持ち上げを検出できたのは 5 本、カゴまでは 1 本。
  失敗した動画でカゴまでの誤検出は 0 本 (答えたときは正しいが、見落としが多い)。
- 物体ごとの失敗率を渡すと、データ追加の提案は人の判断と一致した。決め手は失敗率。
- 詳細: `results/vlm_diagnosis/README.md`

## 中身
- `notebooks/PAI_final_smolvla_libero_plus.ipynb` : 学習・評価・録画のノートブック (Colab, GPU)
- `results/eval/` : 1周目の評価 JSON (`eval_info.json`)
- `tools/diagnose_failures.py` : 自由記述で失敗の種類を診断し、データ追加を提案
- `tools/replan_sweep.py` / `tools/eval_adaptive.py` : 見直し間隔の比較と、つかんだか判定の適応型(Colab で実行)
- `tools/train_blur.py` : 学習画像にぼやけを混ぜる学習(4周目)。`tools/*.py` はノートブック 6.1 のセルが `/content` に書き出す
- `tools/diagnose_frames.py` : 作業領域を切り出し、コマごとに選択肢で答えさせる診断
- `results/vlm_diagnosis/` : VLM 診断の実行ログと、方法ごとの結果
- `results/runs/<run>/` : 各周の設定 `run_config.json`、Object の評価 `object_sweep.json`、
  維持確認 `retention_nas10.json`

## 再現方法
1. Google Colab (GPU) でノートブックを開き、上から順に実行します。
   「すべてのセルを実行」は使わないでください(学習が走ります)。
2. 条件は `PRESETS` に集約しています。`RUN_NAME` で周を切り替えます。
   - 1周目 `r1_spatial` (5000 step, 各5本)
   - 2周目 学習なし。同じモデルを Section 10.2 で `n_action_steps=10` にして評価
   - 3周目 `r3_object` (4000 step, 125 エピソード)
   - 4周目 `r4_blur` (3周目と同じ設定 + ぼやけの水増し。`tools/train_blur.py`)
   - 見直し間隔の比較: 3周目のモデルを復元・マージしたあと、`tools/replan_sweep.py` を `/content` に置いて
     `rs.run_sweep(...)` を実行(5設定 × 30回で約3時間、結果は設定ごとに保存され再開できる)
3. モデルとデータは revision を固定しています。
